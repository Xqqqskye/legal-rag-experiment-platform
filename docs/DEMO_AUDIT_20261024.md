## 发现并修复的问题

| 问题 | 修复 |
|---|---|
| 自动创建会话发生在发送的异常处理之外 | 创建、发送统一进入错误处理，失败保留输入 |
| 单字符补充（如“1”）直接被拒绝 | 允许单字符进入上下文判断；拒绝空白输入 |
| Ctrl+Enter 可重复触发发送 | 发送状态锁，期间禁用切换、新建、删除 |
| 会话异步加载返回乱序 | 加载版本号防止旧响应覆盖新会话 |
| 请求失败留下半轮用户消息 | 成功后以事务提交用户消息、助手消息和记忆 |
| 并发请求读取相同旧记忆 | 按会话串行执行“读上下文—生成—提交” |
| SQLite 连接未显式关闭 | 连接上下文提交/回滚后关闭，避免文件句柄泄漏 |
| 删除会话未保证删除消息 | 启用外键，并兼容清理旧版消息 |
| 首次从旧版记忆切换案件可能丢失原案件 | 切换前保存旧案件；支持按已有 case_id 切回 |
| 闲聊/信息不足可能覆盖案件事实 | 路由状态单独记录，不覆盖案件事实 |
| 纠正记录字段未真正维护 | 提示词明确输出纠正，保存纠正历史和提取来源 |
| 纯向量模式仍执行 BM25 | 根据路由跳过整个词法分支 |
| 纯 BM25 模式先放法条后放案例 | 各语料域按排名融合，避免候选截断天然偏向法条 |
| 一级意图改为英文后批量引用率漏统计 | 统一标准标签再计算 |
| A/B 把闲聊或未评估的引用状态显示为失败 | 没有引用检查结果时显示“未检查 / 不适用” |
| 引用跳转到折叠证据后不可读 | 点击时自动展开对应证据；新会话结果保存联网来源 |
| 泛化网络错误、422 对象错误难以理解 | 同源 API 客户端返回接口地址和字段级错误；GET 有界重试，POST 不自动重发 |

## 实测耗时

环境：本地 CPU FAISS，法条 30,132 块、案例 31,795 块，本地 BM25 兜底，供应商 API 分析与生成。关闭联网核验、LLM 重排和质量评估。

首次临时构建两套 BM25：约 20.96 秒。热状态短查询 BM25：约 0.22 秒，其中案例分支约 0.20 秒。现已将构建移到服务启动阶段。

同一个自编问题“公司拖欠我三个月工资，我应该如何维权？”的两次端到端记录：

| 分段 | 关闭案例 | 开启案例 |
|---|---:|---:|
| 意图/改写 | 8.663s | 4.628s |
| 整体检索墙钟时间 | 0.719s | 1.268s |
| 查询 Embedding | 0.6385s | 0.8278s |
| 案例 BM25 | 未执行 | 1.1955s |
| 案例向量检索 | 未执行 | 0.0199s |
| 回答生成 | 11.360s | 10.641s |
| 总计 | 20.743s | 16.537s |

这些是两次抽样，不是平均值、P95 或因果对照结论。分析模型改写可能不同，API 延迟也会波动。BM25 与编码并行，分支耗时不可相加作为整体检索耗时。此样本开启案例后召回了 18 个案例候选，但最终 Top 5 没选中案例，不能用它估算“新增案例段落”的生成成本。法条与案例由同一次回答调用生成，当前没有独立的案例段落输出计时。

## 复测方式与边界

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test tests/test_api_client.cjs
.venv\Scripts\python.exe scripts/audit_demo.py
# 以下会使用供应商 API，产生少量调用费用
.venv\Scripts\python.exe scripts/audit_demo.py --live
```

离线回归覆盖会话事务、失败保留、单字符与空白、删除关联数据、案件切换、闲聊隔离、案例开关、纯向量路由和批量指标。真实请求覆盖有/无案例的法律问答；界面检查覆盖五个标签页和证据展开。没有穷举所有模型、全部问题、网络环境和长时间并发负载，不能据此保证不存在其他 Bug。

## 案例开关建议

保留“检索参考案例”选项。普通规则查询可关闭；需要裁判思路或类似案例时开启。此次上线保留原来的勾选默认值，让使用者比较后决定。不要仅为展示而强制引用不相关案例。

下一步主要的交互速度收益应来自流式回答和更短的首次回答，避免用户必须等所有文本生成后才能看到第一句；应另外测量首字延迟和完整回答耗时。
